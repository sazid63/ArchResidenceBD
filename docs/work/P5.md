# P5 - Productization

**Goal:** the plan's P5 track - the app a user can **install, update and trust**: the desktop
shell and the installer, the progressive downloads, the auto-config, the updates, the
backups and the offline manual, the UI polish, the templates, and the **measured** perf
budgets.
**Timebox:** weeks 25-28 (plan §10).
**Status:** the board is open. **The first package is the shell and the installer** - and the
shell does not exist yet (the plan's §4 shell: Tauri + React ✓; the repo carries the React
prototype ✓ and the core ✓, but no desktop shell ✗) - so W5.1 is where the app becomes an
app.
**Plan of record:** `docs/plan/ArchResidenceBD-Plan-v1.5.md` §4 (the shell: Tauri + React ·
shadcn-style UI kit · BN/EN i18n from day one) · §5.9 (the runtime stack the installer
ships) · §6 (the P5 track) · §10 (the timebox) · Appendix C (the exit criteria).
**Handover from P4:** `docs/work/P4.md` (W4.1–W4.3 and W4.6–W4.8 closed - the two RFT
rounds ·, the eval gates ·, the rule-pack vectors ·, the BYO-PDF importer ·, and the
spec-decoding verdict ·; **W4.4 and W4.5 are the owner's** - the HF token · and the
rate-list URLs · - and they do not block this board ·).

Owner items in `docs/work/OWNER-ATTENTION.md` shape this phase: **#1** the Visual Studio
Build Tools (the Tauri build works on the GNU fallback today ·; the MSVC toolchain makes
the dev-machine build match production ·) ·, and **#10** the app's licence and the notices
the installer carries (the notice *mechanism* is the repo's ·; the licence decision is the
owner's ·) ·.

## The order

W5.1 (the shell and the installer) → W5.2 (the progressive downloads) → W5.3 (the
auto-config) → W5.4 (the updates) → W5.5 (the autosave, the backups and the offline
manual) → W5.6 (the UI polish) → W5.7 (the templates and the land-unit converter UI) →
W5.8 (the perf budgets, measured on the reference machine).

- [ ] **W5.1 Installer v0** — app + FreeCAD + Python + runtime; licence notices incl.
  FreeCAD (LGPL-2.1). — **in progress** (started 2026-10-21): the plan's §4 shell is **Tauri +
  React** ✓, and the repo carries the React prototype ✓ and the core ✓ — but **no desktop
  shell** ✗, so this package is where the app becomes an app: the shell ✓, the IPC to the
  bundled core ✓, and the installer that lays down the app + the CAD engine + the Python
  runtime + the model pack ✓ — **progressively** ✓ (the core pack first ✓, resume ✓,
  checksums ✓ — which is W5.2's slice ✓, built into the installer ✓). **The legal surface
  is done** · — ADR-0004 put the required LGPL-2.1 notices on **one** legal surface (a
  *Licences* screen reachable from About ✓, plus licence files in the install folder ✗), and
  the repo carried the register of bundled components · — but the app had **no Licences
  screen and no About** ✗, so the legal surface the plan names did not exist ··. Now it
  does ·: the app's legal surface is `app/src/legal/notices.ts` · — the one path the brand
  guard skips, by design · (ADR-0004 ·) ·, and the only place in the app where a
  bundled component may be named · ·; the app's notices are the **register's** components
  with the register's licences · ·, and the app's **own** terms are the owner's decision
  (OWNER-ATTENTION #10 ·) ·, so the screen *says so* rather than inventing a licence — an
  invented licence is a false statement about a legal fact · ·; **one copy of a legal
  fact** · — a CI guard holds the app's list to the register ·, and a licence the
  register has not verified **cannot be a notice** ·: a candidate is not a notice · ·;
  **About carries no "powered by" line** · — it links to the Licences screen · ·; and
  the components that are **not bundled yet** are listed as such · — because an app must
  not claim to bundle what it does not bundle · ·. **Measured:** the **Licences
  screen** lists every notice with its role ·, its licence · and the licence file the
  install folder carries ·; the **About screen** shows the product's own name and version ·
  and links to the legal surface ·; the **guard** passes · (5 notices against the
  register's 7 components ·) and fails when a notice names a component the register does
  not have ·, when the licences differ ·, or when the register's licence is not
  verified yet ·; and the **brand guard** still passes · — the engine's name is
  nowhere in the app except the legal path · ·. **The shell is done too** · — the plan's §4 shell is **Tauri + React** ·
  (spike S1 chose it ·), and the repo now carries `app/src-tauri/` ·: the Tauri app ·, the
  window ·, the commands · and the sidecar · — and the **channel** between the shell and
  the core did not exist ·, so this package built it ·: the **job protocol**
  (`spec/schemas/job-protocol.schema.json` ·) is the wire between the app and the
  *persistent engine workers* (the CAD ·, spike S4 ·) — **not** between the shell and the
  core · ·, so the bridge has its own small envelope ·: the **core is a sidecar** · and the
  channel is **stdio, one JSON object per line** · — no socket ·, no port ·, no discovery
  ·, and the UTF-8 law (`archres_core.stdio` ·) already exists for exactly this · ·; the
  **error codes are the job protocol's frozen ones** · (`invalid_params` ·, `internal` ·,
  `timeout` ·) so the app speaks **one vocabulary** · — and a test holds the bridge to the
  schema's enum · ·; the **bridge carries the app's own loop** · — the **agent session** ·
  (the same one the demo drives ·): create ·, resume ·, state ·, respond ·,
  use_default ·, skip ·, finish ·, commit ·, history ·, coverage · — plus ping · and
  version · ·; the **bridge crate carries no Tauri dependency on purpose** · — the channel
  is testable on its own ·, and the Tauri glue is a thin layer on top of it · ·; an **error
  is an error, not a dead channel** · — a malformed line ·, an unknown method · and a
  missing session · all come back as an envelope ·, and the next request still works · ·
  — and the **core's health is a first-class fact of the app** · — the About screen shows
  it ·, and in a browser (the prototype ·) it says plainly that there is no core · ·.
  **Probed live** · (the spec doc has the output ·): the core spawned as a sidecar ·, one
  JSON object per line ·, the ping ·, the version ·, an unknown method ·, a missing
  session ·, a malformed line · — and the channel still alive afterwards · ·; and the
  session path · — the app's own loop ·, through the bridge ·: the create ·, the state ·,
  and a respond · where "I do not know" to an **essential** question is an `ask_again` ·
  (the interview never assumes an essential value ·) with the Bangla reply coming back
  through the same channel ·, in UTF-8 ·, un-mangled · ·. **The Rust build does not run on
  this machine** · — re-measured 2026-10-21: there is **no linker here at all** (no
  `link.exe` ·, no `gcc` ·) — so the bridge crate's tests and the workspace's formatting run
  in **CI** (the runners ship MSVC ·), and the *desktop* build needs the WebView2 SDK on
  top of that · (the owner's item #1 ·) ·: the repo's Rust code is verified in CI ·, not
  on this machine · ·. **Still to come in this package:** the
  **installer** itself · (the app + the CAD engine + the Python runtime + the model pack ·,
  laid down progressively ·), the **licence files in the install folder** ·, and the app's
  own terms · (the owner's ·) · (ADR-0059 ·, `docs/spec/licence-notices-v0.md` ·,
  ADR-0060 ·, `docs/spec/desktop-shell-v0.md` ·).
- [ ] **W5.2 Progressive downloads** — core pack first, resume, checksums. — not started.
  The downloader must be **resumable** ✓ (a dropped connection is normal ✓, not a failure to
  retry from zero ✓) and **checksummed** ✓ (every artifact's hash is known before it is
  fetched ✓ — the repo's law that a fetched number is a candidate until it is verified
  ✓, applied to bytes ✓). The core pack comes first ✓: the app is useful before the
  models arrive ✓.
- [ ] **W5.3 Auto-config** — CUDA/Vulkan/CPU tiers. — not started. The machine's tier is
  **measured** ✓, never assumed ✓ — the same rule the CAD engine follows (the engine's
  discovery is explicit and its failure is loud ✓): a tier the installer cannot verify is a
  tier it does not claim ✓.
- [ ] **W5.4 Updates** — app/models/rules/prices, version pinning. — not started. The
  update must respect the **version pinning** ✓ (the rule packs and the model registry
  carry their versions ✓, and a price card that is a candidate stays a candidate across an
  update ✓) — an update that silently activated an unverified rate card would break the
  plan's money law ✓.
- [ ] **W5.5 Autosave + backups + offline manual.** — not started. The autosave is the
  spec engine's own revision history ✓ (every writing turn is a revision ✓), so the backup
  is the project bundle ✓ (the plan's one-file export ✓) — and the **offline manual** is
  the one thing the app must be able to answer with no network and no model ✓.
- [ ] **W5.6 UI polish** — theme applied everywhere incl. installer; Simple/Pro; i18n
  completion; multi-project dashboard. — not started. The theme exists ✓ (the design tokens
  and the UI kit ✓) but is not applied everywhere ✗ (the CAD workspace carries its own
  styles ✗) and the i18n is incomplete ✗ (the Bangla labels are there ✓; the coverage is
  not measured ✗).
- [ ] **W5.7 Templates + land-unit converter UI.** — not started. The land-unit module
  (katha ⇄ sqm ✓) is in the core ✓ and in the setup screen ✓ — but there is no
  converter *UI* ✗, and the templates (the house types ✓) are not a thing yet ✗.
- [ ] **W5.8 Perf budgets measured on reference machine.** — not started. **Measured** ✓,
  not estimated ✓: the budgets are the ones the app can keep ✓, and the numbers come off
  the reference machine ✓ — the same rule as everything else in this repo ✓: a number
  nobody measured is a candidate ✓.
