# P5 - Productization

**Goal:** the plan's P5 track - the app a user can **install, update and trust**: the desktop
shell and the installer, the progressive downloads, the auto-config, the updates, the
backups and the offline manual, the UI polish, the templates, and the **measured** perf
budgets.
**Timebox:** weeks 25-28 (plan §10).
**Status:** the board is open. **The first package is the shell and the installer** - and the
shell does not exist yet (the plan's §4 shell: Tauri + React ✓; the repo carries the React
prototype ✓ and the core ✓, but no desktop shell ✗) - so W5.1 is where the app becomes an
app.
**Plan of record:** `docs/plan/ArchResidenceBD-Plan-v1.5.md` §4 (the shell: Tauri + React ·
shadcn-style UI kit · BN/EN i18n from day one) · §5.9 (the runtime stack the installer
ships) · §6 (the P5 track) · §10 (the timebox) · Appendix C (the exit criteria).
**Handover from P4:** `docs/work/P4.md` (W4.1–W4.3 and W4.6–W4.8 closed - the two RFT
rounds ·, the eval gates ·, the rule-pack vectors ·, the BYO-PDF importer ·, and the
spec-decoding verdict ·; **W4.4 and W4.5 are the owner's** - the HF token · and the
rate-list URLs · - and they do not block this board ·).

Owner items in `docs/work/OWNER-ATTENTION.md` shape this phase: **#1** the Visual Studio

## The order

W5.1 (the shell and the installer) → W5.2 (the progressive downloads) → W5.3 (the
auto-config) → W5.4 (the updates) → W5.5 (the autosave, the backups and the offline
manual) → W5.6 (the UI polish) → W5.7 (the templates and the land-unit converter UI) →
W5.8 (the perf budgets, measured on the reference machine).

- [ ] **W5.1 Installer v0** — app + FreeCAD + Python + runtime; licence notices incl.
  FreeCAD (LGPL-2.1). — not started. The plan's §4 shell is **Tauri + React** ✓, and the
  repo carries the React prototype ✓ and the core ✓ — but **no desktop shell** ✗, so this
  package is where the app becomes an app: the shell ✓, the IPC to the bundled core ✓, and
  the installer that lays down the app + the CAD engine + the Python runtime + the model
  pack ✓ — **progressively** ✓ (the core pack first ✓, resume ✓, checksums ✓ —
  which is W5.2's slice ✓, built into the installer ✓). The **licence notices** ✓ are the
  repo's (the bundled engine is LGPL-2.1 ✓, and ADR-0004 keeps its name out of the branding
  ✓, with the notices confined to the app's **Licences** screen ✓) — but **which licence
  the app itself ships under** is the owner's (OWNER-ATTENTION #10 ✓).
- [ ] **W5.2 Progressive downloads** — core pack first, resume, checksums. — not started.
  The downloader must be **resumable** ✓ (a dropped connection is normal ✓, not a failure to
  retry from zero ✓) and **checksummed** ✓ (every artifact's hash is known before it is
  fetched ✓ — the repo's law that a fetched number is a candidate until it is verified
  ✓, applied to bytes ✓). The core pack comes first ✓: the app is useful before the
  models arrive ✓.
- [ ] **W5.3 Auto-config** — CUDA/Vulkan/CPU tiers. — not started. The machine's tier is
  **measured** ✓, never assumed ✓ — the same rule the CAD engine follows (the engine's
  discovery is explicit and its failure is loud ✓): a tier the installer cannot verify is a
  tier it does not claim ✓.
- [ ] **W5.4 Updates** — app/models/rules/prices, version pinning. — not started. The
  update must respect the **version pinning** ✓ (the rule packs and the model registry
  carry their versions ✓, and a price card that is a candidate stays a candidate across an
  update ✓) — an update that silently activated an unverified rate card would break the
  plan's money law ✓.
- [ ] **W5.5 Autosave + backups + offline manual.** — not started. The autosave is the
  spec engine's own revision history ✓ (every writing turn is a revision ✓), so the backup
  is the project bundle ✓ (the plan's one-file export ✓) — and the **offline manual** is
  the one thing the app must be able to answer with no network and no model ✓.
- [ ] **W5.6 UI polish** — theme applied everywhere incl. installer; Simple/Pro; i18n
  completion; multi-project dashboard. — not started. The theme exists ✓ (the design tokens
  and the UI kit ✓) but is not applied everywhere ✗ (the CAD workspace carries its own
  styles ✗) and the i18n is incomplete ✗ (the Bangla labels are there ✓; the coverage is
  not measured ✗).
- [ ] **W5.7 Templates + land-unit converter UI.** — not started. The land-unit module
  (katha ⇄ sqm ✓) is in the core ✓ and in the setup screen ✓ — but there is no
  converter *UI* ✗, and the templates (the house types ✓) are not a thing yet ✗.
- [ ] **W5.8 Perf budgets measured on reference machine.** — not started. **Measured** ✓,
  not estimated ✓: the budgets are the ones the app can keep ✓, and the numbers come off
  the reference machine ✓ — the same rule as everything else in this repo ✓: a number
  nobody measured is a candidate ✓.
