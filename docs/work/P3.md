Notes:

- **Package-closure checklist (unchanged from P1).** A package is not done when the code lands;
  it is done when **all** of these hold, in order:
  1. the full local gate sweep is green — `pytest`, `tools/ci/py_syntax_check.py`,
     `tools/ci/brand_guard.py`, `generate_spec.py --check`, `generate_interfaces.py --check`,
     and every `--check` freshness CLI relevant to the package;
  2. where models or CAD are touched, a **live probe is recorded in the spec doc** with its
     real output — a stubbed transport is a test, not a verification;
  3. the board and spec numbers are true (or the exact count is removed from prose and left
     to CI output — hand-maintained totals drift);
  4. the package is committed, pushed, and CI is green on the commit;
  5. only then is the box on this board ticked — **last**, never first.
- **Quality law (plan §9) applies to the documents like everywhere else:** a rendered document
  is a *claim* about the model, so every number in it must be re-derivable from the model
  (the BOQ's own check does exactly that ✓); a missing capability is an explicit visible state;
  anything not executed and measured is a candidate.
- **The engine's name never appears in a generated document** (ADR-0004) — the drawing sheet
  already carries the pack's "candidate - not for construction" status and no engine name ✓;
  every renderer P3 adds must keep that ✓.
- **Bangla is hand-authored, never machine-translated** — the reports' Bangla text is written,
  not generated, and the render regression (W3.9) is what keeps the glyphs honest.
- **The price service's prices are candidates until a human verifies them** (the owner item in
  `docs/work/OWNER-ATTENTION.md` #8) — a BOQ rendered from a candidate card must say so.
- **The plan's §9 guards:** the rule-pack vectors ✓ (running), the incremental ≡ full-rebuild
  equivalence ✓ (W2.11, running), and the **Bangla rendering regression** ✗ (W3.9) — plus
  **spec fuzzing**, which still has **no package** and needs one (P3 or P4).
