the **model never sees the answer** · — the prompt carries the system and the user turn only · — or the round would teach the model to echo the dataset instead of to parse · ·; a **kept answer becomes a training record** — the scripted question and labels stay ·, and the assistant's turn is the **model's own words** · ·, which is the point of rejection sampling · ·; a **dropped sample is evidence, not waste** — the ledger holds every sample and the reason it was dropped · ·, and the counts say how many *records* ended with a kept answer · ·; the **holdout is never read** — the round samples `data/training/sft-v1/train.jsonl` ·, so the holdout cannot be trained on by accident (ADR-0015 ·) · ·; a **round is a measurement, not a derivation — so there is no `--check`** · — the model's answers are not a function of the input ·, so there is nothing to compare afterwards · ·, the **ledger** is the record · ·, and the freshness law keeps covering the artifacts that *are* derived (the scripted dataset ·, the split ·, the eval case set ·) · ·; the **provenance is in the schema** — `source.kind: "rft"` · (the SFT schema, v0.3.0 ·) — so an RFT record can never be mistaken for a scripted one · ·, and the round's own check is named in the record (`verifyChecks: ["rft.truth"]` ·) · ·; and the **round runs where the models are** — the model artifacts are not in the repo ·, so the owner runs it on the machine that has them · ·, and the tool says so plainly when the fleet is not answering · · and **refuses to write a round of unreachable samples** · — that is a broken environment, not a round · ·. **Measured:** an answer that agrees is **kept** ·; one whose decision differs is **dropped with the reason** ·; an unreadable answer is dropped as *unreadable* ·; a number within a hair of the truth is the same number · — and one that is not, is not ·; the **model never sees the truth** (the test checks the prompt ·, not just the result ·) ·; a kept sample becomes a training record that **validates against the SFT schema** · ·; a dropped sample becomes **no record** · — and a fleet that is down makes every sample *unreachable* ·, so a broken environment cannot look like a model that was wrong · ·; and the **CLI** refuses to write a round when every sample was unreachable · ·. **Declared, not implied:** the **round's own execution** is the owner's — the model artifacts are not in the repo · — and the **retrain** is the owner's environment (W1.6's round was a Kaggle T4 ·) ·: what is here is the data the round produces · and the eval gates that say whether the new model is better · (ADR-0053 ·) ·; - [x] **W4.2 RFT Repair** — the same loop for the repair model. — **implemented 2026-10-21:** W4.2 is the same loop as W4.1 ·, for the **repair** model — and the board was explicit that the two are *one mechanism* ·, so the mechanism was not written twice ·. **But the repair task's truth is not the parse task's truth** ·: a parse answer is judged against **labels** (the generator wrote them ·) ·, and a repair answer is a **macro** ·, and the question is whether it *works* · — which is not a question about the text ·. **Four decisions:** a **fix is judged by the engine, not by its appearance** — there is more than one way to repair a macro ·, so "does the fix look like the known-good one" would be the wrong question ·, and the right one is whether the macro **runs** and the case's expectations hold · — so the truth here is the **engine's verdict** (the real CAD engine ·, the same case the scripted fix had to pass ·) ·, and the verifier is **injected** (the tests use a fake ·, the tool uses the real engine ·) · ·; the **engine's verdict is the only judge** · — a fix that fails is dropped with the engine's own words (the check and its message ·) ·, the same shape as the chat round's reasons · ·, so the ledger reads the same way for both · ·; a **fenced macro is unwrapped** · — the models fence their code ·, and the engine must not be asked to run the fence · ·; and the **failure's truth does not change** · — the record keeps the scripted labels (the case ·, the error type ·, the failure code ·) ·, and the *fix* is what the model produced ·, not what went wrong · ·. **Measured:** a **fenced macro** is unwrapped ·, and an answer with no code is dropped as *unreadable* ·; a fix the engine **verifies** is kept ·, and the payload says which case it ran against · — and a fix that **fails** is dropped with the engine's own message ·; the **round** keeps only the fixes that work · — of two samples, the working one is kept and the broken one is dropped · — and the kept fix becomes a training record whose assistant turn is the model's own macro ·, whose source says `rft` ·, whose check is named (`rft.case` ·), whose labels are still the scripted failure ·, and which **validates against the SFT schema** · ·; and the **CLI** takes the task (`--task repair.fix` ·) and the engine (`--engine` ·) ·, with the repair task's records coming from the repair split's **training side** · (the holdout is never read ·, ADR-0015 ·). **Declared, not implied:** the **round's execution and the retrain** are the owner's machine and environment ·, as in W4.1 · ·; - [x] **W4.7 BYO-PDF importer** — candidate extraction + review UI. — **implemented 2026-10-21:** the plan's law system has three channels (§5.6 ·) and its P4 track asks for the rule packs of the remaining cities (§6 ·) — but some authorities **cannot be redistributed** (the plan's own note ·), and it names the way out: *the BYO-PDF importer path; structured rule data + user-provided copies* ·. So the path is: the user brings their own PDF ·, the app reads it ·, and the clauses in it become candidates a human can look at ·. **What existed** was a PDF *reader* — a tool script, loaded by path from two places · — and nothing that turned a PDF into rule data ·. **Five decisions:** a **candidate is not law** — the importer produces candidates (a number, a page, the text ·), the document says `status: candidate` · and carries no pack keys at all (no `tables` ·, no `authority` ·, no `regime` ·), so nothing in it can be mistaken for a rule · ·, and a rule lives in a **pack** ·, written by hand, from reviewed candidates · ·; **every candidate cites its page** — the same law the price cards follow ·, because a clause without a page cannot be checked · ·; **a human decides, and the decision is recorded** — who, when and why · — a candidate with no decision is visibly unreviewed (`review: null` ·, and the counts carry `unreviewed` ·), so a pack cannot be built from candidates nobody looked at · ·; **the PDF reader is the core's** (`core/src/archres_core/pdf_text.py` ·) — the app is a shell over the core ·, so a user's own PDF has to be readable *from* the core ·, and the price transcriber and the reader's own test import it the ordinary way instead of loading it by path · ·; and the **reader gained a line-preserving mode** (`read_pdf(path, lines=True)` ·) with the **default unchanged** · so the price cards are read exactly as before · · — that was necessary, not decorative: the reader produced the page's words *run together* ·, so a page's provisions were one long run of words and the importer would have found the **first** provision only · — a line is where the text moves to a different height on the page ·, the lightest reading of the layout · ·. **The extraction is a heuristic, and it says so** — a line that begins with a number opens a provision ·, and the lines up to the next one are its body · ·; a book whose provisions are not numbered yields **no candidates** · — a fact, not a failure to be papered over · ·. **Measured:** a one-page PDF with **three provisions** yields **three candidates** ·, each with its own page · — the whole way through the reader ·, not around it ·; the **candidate document** carries the source's hash ·, the counts ·, and each candidate's review ·; the **CLI** writes the document ·, checks it for staleness ·, records a decision ·, and refuses a decision that is neither accepted nor rejected ·, and refuses a decision on a candidate the PDF does not have ·; the **price card is untouched** · — `transcribe_card.py --check` still passes ·, because the reader's default did not change ·; and the **app's review screen** shows the candidates with their page ·, their excerpt · and their state (unreviewed ·, accepted · or rejected ·), and a reviewer can accept or reject each one ·. **Declared, not implied:** **promoting accepted candidates into a pack** is not here — a pack is written by hand, from reviewed candidates ·, and the promotion is a separate slice · ·; **OCR for scanned books** is not here — the reader reads text PDFs, as it always has · ·; and the **screen is the prototype's** (mock data ·, like every other screen ·) — but the shape it shows is the core's candidate document ·, so the screen and the record cannot drift apart · · (ADR-0056 ·, `docs/spec/byo-pdf-importer-v0.md` ·). **Closed 2026-10-21** on commit `6cddc03` (pushed, CI green): 1,087 tests, 248 Python files compile clean, the brand, Bangla and security guards clean, the fuzz guard clean over 1,200 mutants, the app typecheck clean, and the committed candidate price card still complete and still a candidate.

- [x] **W4.8 Spec-decoding verdict** — adopt/parameterize from spike data. ∥ — **implemented 2026-10-21:** the plan (v1.5, frozen) said speculative decoding was **"lossless by construction (P1 pilot)"** — and **spike S2 ran that pilot** and measured the opposite: draft acceptance **~8%** (7.6% CPU, 8.3% GPU), **3.5–11x slower** (16.43 against 57.98 tok/s), **+1.5 GB VRAM** on a 6 GB card that holds one model at a time, and — the decisive finding — **the greedy outputs diverged** from the no-draft baseline in every draft configuration.
