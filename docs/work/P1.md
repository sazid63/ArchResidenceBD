Notes:

- Interfaces frozen (W0.9, ADR-0006) are law for every package here; rule packs stay the only home for rule numbers; every value still carries provenance (plan §2.5).
- Deviation Register schema is already frozen in the verdict interface (W0.9) — W1.2 implements evaluation + restore; register **display/diff** surfaces land with the app shell (P2/P3).
- W1.5's teacher pipeline is built and tested; the **full teacher batch** is a W1.6 job (the committed scripted dataset is ~197k tokens vs the plan's ~0.5M target). The local 4B/3B GGUFs and Kaggle CLI are available; promotion of teacher paraphrases needs the W1.6/W1.9 eval gate — no auto-promotion exists.
- W1.5 dataset law: `data/training/chat-v0/` is committed and pinned; rebuild with `tools/training/build_chat_dataset.py`, CI checks freshness. Counts are pinned in tests, so a flow-book/pack change is a visible review event.
- W1.2 decision: phase data is addressed by phase slug (`/phases/site-excavation/data/…`) — flow book, verdict sets and spec engine all agree (ADR-0008); W1.4 maps answers straight to these pointers.
- W1.2 coverage is declared, not implied: `coverage(pack)` + `docs/spec/rule-engine-v0.md` list the provisions not yet evaluated; every run surfaces the pack's own gaps as `unevaluated(pack_gap)` rows.
- W1.4 decision: answers have a semantic value and a declared write mapping (three vocabulary bridges); bare numbers use the project's display unit (`medium` confidence), explicit units win; `when` conditions read answers seeded from the spec so phase-scoped/resumed runs work; unresolvable registry/derive fallbacks become `pending` items, never invented values (ADR-0010).
- W1.10 decisions (ADR-0011): revisions are recorded as snapshots (`SpecStore.commit_snapshot`), not by re-applying ops, so W1.4's per-path provenance survives; one revision per writing turn, `finish()` batches; the model is one seam (`agent.client`) and loopback-only; context budgets are alarms, never truncation; injection findings are recorded and fence the prompt but never refuse the user's answer, while a high finding denies tool calls; tools are deny-by-default and **no executor is wired in core** (W3.10 owns execution + approval UX).
- W1.11 decisions (ADR-0012): the registry is the only model manifest and the router YAML is generated/committed; a mode is a warmup order (interview = chat first, design = repair first), never a new member; readiness is HTTP, not a banner; the launcher injects `ARCHRES_ROOT` and refuses non-loopback URLs. The real v265 binary and S2 GGUFs were exercised, not just unit-tested.
