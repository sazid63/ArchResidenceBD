- **Package-closure checklist (agreed 2026-10-10, after W1.1's first "done" outran its fixes).**
  A package is not done when the code lands; it is done when **all** of these hold, in order:
  1. the full local gate sweep is green — `pytest`, `tools/ci/py_syntax_check.py`,
     `tools/ci/brand_guard.py`, `generate_spec.py --check`, `generate_interfaces.py --check`,
     and every `--check` freshness CLI relevant to the package;
  2. where models or CAD are touched, a **live probe is recorded in the spec doc** with its
     real output — a stubbed transport is a test, not a verification;
  3. the board and spec numbers are true (or the exact count is removed from prose and left
     to CI output — hand-maintained totals drift);
  4. the package is committed, pushed, and CI is green on the commit;
  5. only then is the box on this board ticked — **last**, never first.

- W1.9 decisions (ADR-0015): the case set is generated from pinned sources and `--check`ed in CI, never hand-maintained; the split is frozen by `sha256(seed:questionId)[0] < 96` **before** training and `--init-split` is a one-off reviewed act; deterministic suites are gated at 1.0 while the model suite is gated at the recorded stock baseline (a floor moves only as a reviewed event quoting the measured number, model and commit); the `parse` suite gates the parser's **safety** contract (`neverStalled`, `agreement:clean`) and *reports* per-operator agreement as visible deferral, because the dataset labels are the assisted-path target rather than parser output; a model case passes only when decision **and** value are right (accepting a wrong value is the failure that reaches the user as a clean confirmation); a gap is either a scored `declared_gap` case or a reported `coverage_probe`, never a deletion; recorded replies are committed because CI cannot start a fleet, and re-recording is a deliberate commit. Declared gap: `LawDesk` is the chat seam but **not wired into `Session`** — that is P2 chat-shell work.
- W1.9 found a W1.5 data defect and fixed it at the source: all six `affirm_sloppy` records labelled an affirmative answer ("yup", "হ্যাঁ হ্যাঁ") as `value: false` because the operator kept the base value — which would have taught W1.6 that "yes" means "no". The operator now returns `value: true`, the dataset verifier recomputes from it, the dataset was rebuilt under a new sha, and a regression test pins every committed record; the stock reply file was not re-recorded (prompts unchanged), so the correction shows as two more passes rather than a re-baseline.
- W1.9 measurements that are recorded, not glossed: the deterministic parser agrees with the dataset on ~72 % of recorded answers and the misses are listed per operator (`omit_unit`, `maybe`, `typo`, BN `dont_know`, BN "হুম") as W1.4 headroom; the stock 4B emits plausible synonyms instead of canonical tokens (`RAJUK`, `on-site`, `no_preference`) and once invented a decision outside the vocabulary; the English parking-row clause retrieves at rank 4 while its Bangla twin is rank 2; and the four corpus coverage probes all come back `retrieved` from a neighbouring provision instead of abstaining — a product gap now visible on every run.
