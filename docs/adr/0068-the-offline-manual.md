# ADR-0068 — The offline manual: derived from the repo's facts, searched without a model

**Date:** 2026-10-22 · **Status:** accepted · **Work package:** W5.5 (the autosave, the
backups and the offline manual — the manual slice) · **Plan:** §10 (the offline-first law) ·
§5.1 (the app's own guidance) · **Related:** ADR-0067 (the bundle), ADR-0003 (the rule
pack)
**Code:** `core/src/archres_core/manual.py` (the entries · the search ·) ·
`core/src/archres_core/bridge.py` (`manual.search` ·) ·
`tools/install/build_manual.py` (the CLI ·) · `app/src/screens/HelpScreen.tsx` (the help
screen ·) · **Tests:** `core/tests/test_manual.py` (10) · **Spec:**

## Context

The plan's W5.5 ends with *"the **offline manual**"* ✓, and the plan's law says the app
works with **no internet** ✓ (§10 ·) ✓. So the manual is the one thing the app must be able
to answer **with no network and no model** ✓ — and that rules out the obvious
implementation: a manual that needs a model to read it is not offline ✓ ✓.

Nothing in the repo could answer a user's question about the app without a model ✓ ✓.

## Decisions

1. **The manual is derived from the repo's own facts** ✓ — the **flow book** ✓ (the
   questions the app asks ✓ and why ✓) and the **rule packs** ✓ (the provisions the app
   applies ✓, with their clauses ✓) — so it is **generated by a script** ✓ and never by a
   model ✓ (the repo's "scripts first, AI last-mile" law ✓ ✓).
2. **Every answer is sourced** ✓ — the flow question id ✓ or the pack's provision and its
   clause ✓ — so a user can check it ✓ and a support answer can point at it ✓ (the
   provenance law ✓ ✓).
3. **Every entry is in both languages** ✓ — Bangla and English ✓ ✓ — because the product
   speaks Bangla ✓ ✓.
4. **The search is deterministic** ✓ — term overlap ✓, a question's own words counting for
   more ✓, and the order stable ✓ (the score ✓, then the entry's id ✓) ✓, so the same
   question always gives the same answer ✓ ✓.
5. **Silence is honest** ✓ — a query that matches nothing returns **nothing** ✓, because a
   manual that invents an answer is worse than one that says "not found" ✓ ✓.
6. **It is reachable from the app** ✓ — the bridge carries `manual.search` ✓ and the app has
   a **Help** screen ✓ — and in a browser (the prototype ✓) it says plainly that the
   manual is searched by the core ✓ ✓.

## Consequences

- **The app can answer offline** ✓ — with no network ✓ and no model ✓ ✓, in the user's
  language ✓ ✓, from facts the repo already holds ✓ ✓.
- **The answers are checkable** ✓ — each carries its source ✓ ✓.
- **The manual cannot drift from the app** ✓ — it is *generated* from the flow book and the
  packs ✓, so a change to the questions changes the manual ✓ ✓.
- **What is not here** ✓: the manual as a **PDF** ✓ (the app reads it ✓ — the screen ✓ —
  and a PDF would be a second copy of the same facts ✓ ✗), and the **screenshots** ✓ ✗.
